# AGENTS.md

Rambl is a local-first push-to-talk dictation app (C# / .NET 11 MAUI). A shortcut records the microphone, a local speech model transcribes it, optional post-processing rewrites the text with a local language model, an optional voice command set lets a decision model press keys instead, and the result is pasted into the focused app. Separately, read-aloud profiles read the selected text (or the clipboard) with a local voice, after optional rewriting steps. Windows is the working target; Mac Catalyst builds, but has no global shortcuts, dictation card, audio devices or native model runtimes yet.

## Validate

- `global.json` selects .NET SDK 11.0.100 (patch roll-forward) and workload set 11.100.1; `src/Rambl.csproj` pins MAUI 11.0.0. Run `dotnet workload install maui-windows` from the repository root after installing the SDK or upgrading the checkout (`sudo dotnet workload install maui-maccatalyst` on macOS).
- Windows: `dotnet build src\Rambl.csproj -f net11.0-windows10.0.19041.0`. Install Visual Studio's Desktop development with C++ workload, including CMake. The first build needs internet: it downloads pinned native releases (parakeet.cpp, transcribe.cpp, audio.cpp, Kokoro's eSpeak phonemizer, the Silero VAD model) and llama.cpp source into `.native/`, verifies their SHA-256 pins in `Rambl.csproj`, and builds the private language runtime.
- macOS: `dotnet build src/Rambl.csproj -f net11.0-maccatalyst -r maccatalyst-arm64` (`maccatalyst-x64` on Intel).
- Shared-installation smoke checks: `dotnet run --project tools/OmniSmoke -- --storage-only`. Full native checks: `dotnet run --project tools/OmniSmoke`, after building the app and placing the pinned Omni backbone and projector in `.native/omni-tests/models/` (see `docs/native-inference.md`). The harness links production model/runtime code and uses files under `.native`, not app data. It also uses an existing installed Parakeet model for a read-only coexistence check when available. Check UI changes by running the app (`src\bin\Debug\net11.0-windows10.0.19041.0\win-x64\Rambl.exe`).
- For native loading or packaging changes, also test `rambl.ps1 build` and the hybrid single-file smoke publish described in `docs/native-inference.md`. Include silence skipping, repeated recordings, padded final windows and unavailable native dependencies; a debug-only test does not cover bundle extraction.
- Dictation card lifetime checks: `dotnet run --project tools/OmniSmoke -- --dictation-only`. They run the production coordinator with controlled speech, post-processing, recording and insertion, without a microphone or app-data changes.
- Startup settings checks: `dotnet run --project tools/OmniSmoke -- --settings-only`. They test TOML migration, independent startup preferences and invalid-file preservation under `.native`, without changing app data or Windows registration.
- When a change makes a fact here untrue, fix this file in the same change.

## Code conventions

- One top-level type per file, named after it. Every member has an explicit accessibility modifier (`.editorconfig`, IDE0040).
- XAML components live in their own folder (`Components/KeyCaps/KeyCaps.xaml`); screens and layouts drop the `View`/`Layout` suffix. A layer of a screen (`ProcessEditor`, `HistorySettings`, `ModelsTab`) sits in that screen's folder. `App` and `RamblWindow` stay at `src/`.
- Namespaces: `Views`, `Components` and `Layouts` use the category (`Rambl.Views`); `Features`, `Common` and `Platforms` follow the folder (`Rambl.Features.VoiceCommands`, `Rambl.Platforms.Windows.Input`).
- Dependencies: `Common` depends on nothing else in the app. Components may use `Common`, never `Features`, `Views` or `Layouts`; when a component needs a feature's type, move the type to `Common` or pass plain values. Windows-only code goes under `Platforms/Windows/<Area>/`, never loose in `Platforms/Windows`.
- Native runtimes are gated per platform in `Rambl.csproj` (`UseSherpaOnnx`, `UseParakeetCpp`, `UseTranscribeCpp`, `UseLlamaCpp`, `UseAudioCpp`, `UseOnnxRuntime`, each defining a symbol used in `RamblProgram`). Keep Windows-only code out of Mac Catalyst builds.

## Architecture constraints

- The pipeline is Record → STT → post-processing → voice command → result executors, built from replaceable parts (`DictationCoordinator`, `PostProcessChain`, `VoiceCommandRunner`, `IResultExecutor`). A failed stage must never lose what was dictated: the recording and transcript are saved before later stages run.
- Read aloud is its own flow (`ReadAloudSession`: profile steps through `PostProcessChain`, then `TtsEngine` sentence by sentence into an `IAudioStream`). A shortcut either dictates (dictation, processes, command sets) or reads aloud (profiles, which may share one and then read in order), never both; check new shortcuts with `ShortcutUsage`. A profile that saves to the History keeps each reading through `RecordingHistory` (`BeginReading`, `SaveReadingAsync`) at the voice's sample rate; `RecordingInfo.Reading` marks it, and readings are never retranscribed.
- Read-aloud profiles may apply a local voice effect through `VoiceEffectProcessor` after synthesis and before playback and History saving: Walkie-talkie (`RadioVoiceSettings`), Robot (`RobotVoiceSettings`) or Spacesuit / Mission Control (`SpacesuitVoiceSettings`). Only one effect runs; imported files enabling several use Spacesuit, then Robot, then radio. None preserves the original audio and remembers each effect's controls. Keep filter/oscillator state between sentences at the same sample rate. Robot pitch is the metallic carrier frequency, not a shift of the speaker's pitch. Transmission squelches and headset beeps belong at the start and end of a reading, never each sentence; sentence timing excludes them, and playback must drain the closing sound before finishing.
- No Shell. `Layouts/AppLayout` swaps screens resolved from DI; each sidebar `NavItem` names its screen type. `App` must resolve `AppLayout` inside `CreateWindow`, never in its constructor, or XAML is parsed before resources exist and the app crashes on startup.
- Settings live in `config.toml` (`%LOCALAPPDATA%\User Name\jam.rambl\` on Windows), read and written by `SettingsService` with Tomlyn. Change settings only through `App.UpdateSettingsAsync`. Unknown keys are preserved and invalid TOML is never overwritten. Models, language models, processes, command sets and recordings are folders next to it.
- Windows startup settings live in `[startup]`: `start_with_windows` registers the quoted external `Rambl.exe` path in the current user's Run key; `start_minimized` hides the main window after launch only if its tray icon was created. Both default off and work independently. Startup controls are hidden on Mac Catalyst. Changing Start with Windows rolls back the saved preference if registration fails; uninstall removes only an entry pointing to that installation.
- `ModelLibrary`, `LanguageEngine`, `DecisionEngine`, `TtsEngine`, `VoicePreview` and `ReadAloudSession` must be called from the UI thread.
- The global keyboard and mouse hook (`GlobalInputHook`) runs on a dedicated message-loop thread and only classifies events; actions run later on the UI thread, because Windows drops slow hooks. Input Rambl sends itself carries `InjectedInput.Marker` and must pass the hook untouched.
- An exception thrown in a dispatcher callback shows up only as a "CoreMessagingXP.dll 0xc000027b" Windows error. Look in `crash.log` next to `config.toml` first.
- The dictation card (`DictationOverlayWindow`) is a plain WinUI window shown with `WS_EX_NOACTIVATE`. Never activate it, or the app being dictated into loses focus and the paste goes nowhere. The reader panel (`ReaderPanelWindow`) is shown the same way; its selects open lists inside the panel instead of pop-ups.
- On push-to-talk release, keep the dictation card visible in a neutral Transcribing state (indeterminate spinner/wave, frozen recording duration) through speech completion and result insertion. Only post-processing uses violet and Skip. A new dictation waits for this pipeline to finish. Cancel transcription or Esc stops inference without discarding the completed History recording; cancellation while still recording keeps its existing discard behavior.
- Windows releases use a self-contained Inno Setup installer. `rambl.ps1 setup` publishes the app with its pinned native runtimes and bundles a Microsoft-signed x64 Visual C++ Redistributable; the workflow uploads only `Rambl-Setup.exe`. Installation and first launch do not download runtime files.
- Locate files shipped beside the executable through `Common/IO/ApplicationFiles.BaseDirectory`. `rambl.ps1 build` extracts its single-file bundle to a temporary folder, so `AppContext.BaseDirectory` does not locate the external native runtimes, VAD model or icon in that build.
- The installer checks for the x64 Visual C++ Redistributable and offers to install its bundled copy if absent. Only this prerequisite needs elevation; a requested reboot stops setup until it is run again. Silent setup requires the prerequisite already installed.
- Inference must run natively inside Rambl; do not add llama-server, Ollama, or other model-server dependencies. Language inference uses `llama.cpp/rambl-llama.dll`, built from pinned source with llama.cpp, ggml and chat-template support statically linked. No upstream ggml DLLs or server executables are shipped for this runtime. Native faults can affect Rambl; process isolation is no longer assumed. All app-owned native import paths share `Common/Interop/NativeLibraryImports` because .NET permits only one resolver per assembly. transcribe.cpp cannot run two sessions of one model at once; keep its `Gate`.
- Ship both private llama.cpp CPU variants: baseline `rambl-llama.dll` and optimized `rambl-llama-avx2.dll`. `LlamaLibrary` chooses one before any native load, requiring OS-enabled AVX2/FMA and the F16C CPUID bit for the optimized variant. Never enable host-specific `GGML_NATIVE` for distributed builds or remove the compatible fallback. Both variants statically link ggml; only the selected DLL and one set of model weights load.
- LFM3 Omni serves native STT, text post-processing and TTS through `Features/Inference/LlamaCpp`. Its one entry in `multimodal-models.json` is projected into all three task catalogs; all task libraries forward download, cancellation, installed state and deletion to the shared library and `shared-models` store. Never duplicate its weights in task-specific stores or runtime caches. `OmniModelPool` owns one backbone/context/projector per installed artifact, serializes modalities, and unloads after five minutes without use. Adapters do not own the weights. Deletion waits for active inference, unloads the native owner and rejects stale adapters until a new download completes. Upgrading the earlier text-only installation reuses and verifies its backbone, keeps the original on cancellation, and removes the superseded copy only after the full shared installation commits. Omni STT is buffered, resamples to 16 kHz and segments long recordings; TTS emits mono 24 kHz with Female/Male voices and pitch-preserving local speed control. No Omni GPU or vision controls are exposed. d1-Omni remains a separate, unimplemented decision adapter. See `docs/native-inference.md`.
- The existing Qwen3-TTS CustomVoice and Kokoro audio.cpp paths still run in a server process; this is legacy work to migrate, not compliance with the native-only requirement. Qwen's Local model card offers Automatic, CPU and GPU (Vulkan), saved by model id in `[models.devices]`. Automatic tries Vulkan device 0 and falls back to CPU if loading fails; explicit GPU reports failures without falling back. A changed preference reloads the model on its next synthesis. The server stays loaded between sentences and is ended on cancellation, failure, idle unload or app exit; the next request starts fresh. Its WAV output is mono 24 kHz; speed changes use local pitch-preserving overlap-add. Keep `AudioCppSynthesizer.ExpectedVersion` in step with `AudioCppVersion` and its archive hash.
- Kokoro has both sherpa-onnx CPU and audio.cpp GGUF artifacts under the same model id and voice ids. Its processor select sits beside Voice in TTS Models and below Voice in the Read Aloud profile editor, which shares the per-model preference and saves it immediately: CPU prefers the installed sherpa artifact; GPU downloads the extra GGUF if needed, and Automatic prefers audio.cpp once downloaded. A pending download offers Cancel and leaves the prior preference unchanged on cancellation or failure. audio.cpp uses Kokoro's native speed control and the voice's full language code (`en-us` / `en-gb`). Its eSpeak DLL and matching dictionaries are extracted from the pinned espeakng-loader wheel and shipped only beside the server, with their GPL license and source notice; no Python installation is needed.
- The managed ONNX Runtime (`Microsoft.ML.OnnxRuntime.Managed`) runs on the `onnxruntime.dll` that sherpa-onnx ships. Keep both on the same minor version, and never add a second native ONNX Runtime.
- Keep sherpa-onnx on 1.13.8 until an external phonemizer is integrated: 2.x removes the built-in eSpeak frontend needed by Piper and Kokoro's out-of-lexicon words. Test both voice families when upgrading it.
- `SherpaLibrary` loads native Sherpa and ONNX Runtime from beside the executable and checks Sherpa's version before creating any native-backed object. A failed Sherpa constructor can leave a finalizer that throws and terminates the process, so keep that availability check before VAD, STT and TTS construction. Clamp Silero's padded final ranges to the recording length. Publishing must always replace Sherpa's native DLLs: `PreserveNewest` can retain a newer-timestamped DLL after a package downgrade.
- Updating a native runtime pin means changing its version, its SHA-256 and the version or ABI constant the code checks (`ParakeetNative.AbiVersion`, `TranscribeNative.Version`).

## Model catalogs

- `src/Resources/Raw/stt-models.json`, `language-models.json`, `tts-models.json`, the single shared-model catalog `multimodal-models.json`, and common metadata `models.json`. Shared model entries declare `capabilities` (`stt`, `text`, `tts`) and optional `audioLanguages`; `ModelCatalogProvider` merges them into the task catalogs. List only anonymously downloadable, ungated Hugging Face repositories, pinned to a 40-character commit, with each file's size and SHA-256.
- Never hand-edit hashes or revisions; regenerate them from the Hugging Face API.
- Regenerate the Qwen3-TTS CustomVoice catalog entry with `tools/Update-QwenTtsCatalog.ps1`.
- Regenerate Kokoro's additional audio.cpp artifact with `tools/Update-KokoroTtsCatalog.ps1`.
- Regenerate LFM3 Text and the shared Omni backbone/projector artifact with `tools/Update-Lfm3Catalog.ps1`. Keep `LlamaNative.Version` in step with `LlamaCppVersion`; increment the bridge ABI and managed `LlamaNative.AbiVersion` together when its C boundary changes (currently ABI 2).
- Laya (voice commands) is sensitive to wording. `CommandMatcher` asks with a fixed instruction, `The user said: "…"` and a built-in "None" option, and `LayaSettings` never uses a temperature below 1. These were measured against the model's reference code; re-measure before changing them.

## UI and design

- `docs/design.pen` is the design source of truth. Read and edit it only through the Pencil MCP. Git treats it as binary; use `git diff --text`.
- Colors are tokens in `Resources/Styles/Colors.xaml` as `<Token>Light`/`<Token>Dark` pairs, used through `AppThemeBinding`. Never hard-code colors. `.pen` alpha colors are `#RRGGBBAA`; MAUI expects `#AARRGGBB`.
- `processing` (violet) means post-processing only, `accent` means recording, `speaking` (blue) means reading aloud, `danger` (with `danger-border`, `danger-soft`) marks every destructive action.
- Confirmations go through `IConfirmService` (so destructive answers get the danger color), never `DisplayAlertAsync`.
- Lists are sorted A–Z by name, ordinal and ignoring case, after any "Any"/"Automatic" entry. Exceptions: the active model comes first on STT Models Local, and processes keep the user's order within a shortcut.
- The sidebar is grouped, with dividers: History | Post Processing, Read Aloud, Voice Commands | Language Models, STT Models, TTS Models | settings A–Z (Appearance, Audio, Controls); About sits at the bottom. The app opens on Controls.
- History displays at most 10 recordings per page, newest first. Search covers the full history and resets to the first page; Previous/Next clamp after deletions. Keep only the page's cards plus an active playback card, rather than building the entire history on the UI thread.
- Icons are the Lucide font. Codepoints are pinned to lucide-static 1.70.0 in `Components/Icons.cs`; add new ones there and to its name map.
- MAUI quirks that already cost time:
  - `Border` can't stroke single sides; use `BoxView` dividers.
  - A button's own icon and text layout is off-center. Lay out labels and put a transparent button on top, as the topmost child.
  - Don't set `TextColor` or `FontFamily` locally on `NavItem` labels; it breaks the selected state.
  - A new kind of clickable control needs the hand cursor mapping in `RamblProgram`.
  - A `FlexLayout` inside a horizontal stack has no width to wrap at.
  - Don't reassign unchanged values on `RecordingCard` (UI Automation hangs).
  - Size the overlay card with `DictationOverlay.MeasureCard`, not `Measure`.

## Testing the running app

- Before sending keys or clicks, check that Rambl is the foreground window. Input sent while Pencil was in front once edited `docs/design.pen`.
- Remove test data afterwards (test models, processes, command sets, recordings under `%LOCALAPPDATA%\User Name\jam.rambl`), and set the theme back to System.
